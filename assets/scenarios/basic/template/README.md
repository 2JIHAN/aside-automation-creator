# __AUTOMATION_NAME__

지정 폴더의 파일 목록 보고서를 만들고 결과를 알리는 기본 예제입니다. 입력 폴더 바로 아래의 일반 `.txt` 파일만 조회합니다. 본문과 원본은 건드리지 않습니다.

## 실행 전 설정

`workflow/context.md`의 계정, 입력 폴더, 알림 대상과 방법, 시간대를 확정합니다. 실행기와 설치 파일의 모든 자리표시자도 바꿉니다. 실제 입력 조회, 보고서 생성과 외부 전송 권한을 받은 뒤 실행합니다.

## 흐름과 파일

`workflow/flow.json`은 `work → notify → cleanup`을 연결합니다. 보고서 작성, 전송과 정리는 성공 기준과 재실행 위험이 달라 나눴습니다. `review`는 실패 원인과 복구 근거만 확인하고 같은 업무로 최대 두 번 복귀합니다. `review-notify`는 같은 검토 지침을 공유하지만 직접 전송하지 않습니다. 이미 보냈거나 전송 여부가 불명확하면 다시 보내지 않습니다.

정상 실행은 `ok`로 끝나고 학습을 생략합니다. 예외, 복구와 후보 시험 때만 `learn`으로 갑니다. 미해결 업무라도 실패 알림과 정리가 끝나면 `handed_off`입니다. 알림 또는 정리 실패는 `incomplete`입니다. `학습불가`는 성공한 업무 결과를 지우지 않습니다. CLI 오류나 잘못된 상태 응답은 엔진이 `stopped`로 기록하며 자동 정리를 보장하지 않으므로 기록을 확인해야 합니다.

`workflow/memory.md`는 검증한 경험과 진행 중인 후보를 담습니다. 학습의 범위, 사전 검증과 되돌리기 규칙은 `workflow/steps/learn.md`를 따릅니다. 정리는 현재 실행이 만든 것으로 기록한 임시 자원만 대상으로 하며 보고서, 증거와 입력은 보존합니다.

## 수동 실행과 예약

macOS 또는 Linux에서는 `./run.sh`, Windows에서는 `./run.ps1`을 실행합니다. 실행기는 설치된 공통 엔진을 사용하고 현재 계정 목록에서 이메일이 유일하게 일치하는 계정을 찾습니다.

`maintenance/install.sh`와 `maintenance/install.ps1`은 매시간 지정 분에 실행하는 예약 예시입니다. 시간대와 실행 분을 확인하고 별도 승인 후 설치합니다. 같은 폴더의 `uninstall.sh` 또는 `uninstall.ps1`로 해제합니다. 템플릿 복사나 테스트만으로는 예약이 등록되지 않습니다.

## 모의 검증

`ASIDE_AUTOMATION_CREATOR_REPO=/path/to/aside-automation-creator node --test maintenance/tests/*.test.mjs`로 검사합니다. 실제 공유 엔진을 가짜 CLI와 임시 HOME에서 실행하며 실제 외부 CLI, 사이트, 전송이나 예약을 호출하지 않습니다. 분기, 재확인 제한, 계정 선택과 설치 가드를 검증합니다. 지침의 중복 방지와 소유권 규칙은 정적 검사입니다. 실제 에이전트의 파일 처리, 알림과 정리를 검증한 것은 아닙니다.

학습 허용 여부와 수정 범위는 `workflow/context.md`의 `__LEARNING_POLICY__`에 확정해 둡니다. 허용하지 않거나 미확정이면 학습 단계는 지침과 메모리를 바꾸지 않습니다.
