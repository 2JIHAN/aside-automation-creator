# 학습 단계

먼저 공통 지침에서 사용자가 확정한 학습 허용 여부와 수정 범위를 확인합니다. 학습이 금지됐거나 범위가 미확정이면 지침과 메모리를 바꾸지 않습니다. 현재 실행 증거에 미수행 이유를 남기고 `학습불가`로 보고합니다. 아래 허용 범위도 사용자 승인보다 넓게 적용하지 않습니다.

이번 세션의 작업 기록과 단계별 증거, `workflow/memory.md`를 살펴봅니다. 메모리가 없으면 새로 만듭니다. 사실과 추측을 구분하고 중복되거나 더는 유효하지 않은 내용은 정리합니다. 끝난 시험은 결론과 근거만 남기되, 미해결 문제와 진행 중인 시험 기록은 유지합니다. 개선할 근거가 없다면 파일을 바꾸지 않습니다.

## 구조 판단

개선안을 만들기 전에 이 시나리오의 [스텝 경계 체크리스트](../step-boundary-checklist.md)를 확인합니다. 자료를 읽을 수 없으면 구조 변경은 보류합니다.

## 바꿀 수 있는 범위

수정할 수 있는 파일은 다음과 같습니다.
- `workflow/memory.md`
- 후보 MD와 후보 `flow.json`
- 아래 범위에서 수정하는 정식 `workflow/flow.json`
- 정식 원문을 보관하는 학습 증거 파일

민감한 정보는 저장하지 않습니다. 정식 MD는 검증한 후보를 채택할 때만 바꾸며, 다른 실행에서 사용 중인 파일은 덮어쓰지 않습니다.

기존 업무 목적과 권한 안에서 스텝 MD를 개선하거나 스텝을 합치고 나눌 수 있습니다. 필요한 스텝과 조건 분기도 추가할 수 있습니다. 이를 위해 `flow.json`의 `startStep`, `steps`와 상태 선언을 수정할 수 있습니다. 기존 상태의 의미와 초기값은 유지합니다. 시험을 시작할 때만 `initialState.학습계기`를 `후보시험`으로 바꿉니다.

계정, 대상과 외부 변경 권한은 기존 범위를 넓히거나 우회하지 않습니다. 필수 알림과 수신자, 성공 기준, 예약과 재시도 상한도 그대로 지킵니다. 단계 이름을 바꿔 같은 업무의 재확인 한도를 초기화하지 않습니다.

이 학습 지침과 `learn` 단계의 권한 및 진입 조건은 바꾸지 않습니다. 엔진, 실행기, 설치 설정, 공통 지침과 검증 기준도 수정하지 않습니다.

## 후보 작성과 사전 검증

1. 이번 실행에서 사용한 정식 흐름과 수정할 MD 원문을 학습 증거 폴더에 한 묶음으로 보관합니다. 이미 시험 중이라면 처음 보관한 원문과 경로를 유지합니다. 변경 이유, 체크리스트에 따른 판단, 성공 기준, 바꿀 파일과 되돌릴 위치를 메모리에 적습니다.
2. 정식 MD는 그대로 두고 후보 MD와 후보 전체 흐름을 작성합니다. 새 분기를 판단할 근거, 허용할 응답과 상태 전달 방법을 적습니다. `contextFile`과 기존 권한은 유지하며, 한 번에 구조 후보 하나만 시험합니다.
3. 임시 사본에 후보를 적용합니다. 파일과 목적지, 상태 선언, 조건에 맞는 분기가 하나인지, 복귀와 종료가 올바른지 확인합니다. 기존 경로와 바꾼 경로를 모의 테스트한 뒤 스텝 경계를 다시 점검합니다. 모의 검사 대신 실제 외부 작업이나 전송을 하거나, 시험을 위해 같은 변경과 발송을 반복하지 않습니다.
4. 기존 테스트가 현재 구조에 묶여 있어 후보를 검사할 수 없거나 검사가 실패하면 정식 흐름을 유지합니다. 필요한 테스트 보완은 제안으로 남깁니다. 통과시키려고 기존 테스트를 지우거나 기대 결과와 검증 기준을 낮추지 않습니다.
5. 검사를 통과하면 후보 MD를 먼저 준비하고 마지막에 `flow.json`을 원자적으로 교체합니다. 현재 실행은 이미 읽은 흐름대로 마치고 후보는 다음 실행부터 적용합니다. 다른 실행의 파일 수정과 충돌하면 적용하지 않습니다. `학습계기`는 `후보시험`으로 설정합니다.

## 실제 시험과 채택

이번 실행에 실제로 전달된 후보와 작업 증거를 평가합니다. 후보를 실제로 수행했고 성공 기준도 충족한 실행만 셉니다. 방금 만든 후보는 아직 검증한 것이 아닙니다. 대상 예외를 만나지 않았다면 그 예외 대응도 검증됐다고 기록하지 않습니다.

대상 예외, 바꾼 분기와 기존 정상 동작까지 세 차례 정도 성공적으로 확인하면 후보 전체 흐름을 정식으로 채택합니다. 실패하거나 기존 동작을 망가뜨렸다면 보관한 정식 흐름과 원래 지침 연결로 되돌립니다. 시험이 끝나면 `학습계기`를 `없음`으로 돌립니다. 후보 내용이 바뀌면 성공 횟수는 새로 셉니다. 채택하거나 되돌린 이유를 메모리에 남깁니다.

되돌릴 때는 이미 수행한 외부 변경과 전송 내역도 메모리에 적습니다. 같은 작업을 중복해서 수행하지 않도록 합니다.

## 보고

수정한 파일을 다시 읽어 확인합니다. 실제로 바꾼 내용, 후보를 검증한 범위와 아직 확인하지 못한 부분, 다음 실행부터 적용되는지를 짧게 보고합니다. 필요한 검증이나 반영을 끝내지 못했다면 `학습불가`로 보고합니다.
