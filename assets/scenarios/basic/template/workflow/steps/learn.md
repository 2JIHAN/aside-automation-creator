# 학습 단계

확정된 학습 허용 여부와 수정 범위 안에서 작업합니다. 금지됐거나 범위가 미확정이면 지침과 학습 내용을 바꾸지 않고, 현재 실행 증거에 미수행 이유를 남긴 뒤 `학습불가`로 보고합니다.

## 확정 지식 반영

이번 세션의 작업 기록과 사용자 피드백에서 확정된 내용과 미검증 개선안을 구분합니다. 이미 공유한 문서별 역할을 기준으로 반영 위치를 찾습니다. 명확한 사용자 피드백과 검증이 끝난 지식은 허용된 스텝이나 참조 자료에 직접 반영하며, 아래 후보 시험을 다시 거치게 하지 않습니다. 특정 대상의 사실은 그 적용 범위를 유지합니다. 확정 내용의 직접 반영은 후보를 만들거나 `학습계기`를 `후보시험`으로 바꾸지 않습니다.

어떤 확정 항목이든 첫 수정 전에 대상 파일을 이번 턴 증거 폴더에 파일 그대로 복사하고 원문과 같은지 확인합니다. 같은 실행에서 여러 항목을 반영해도 이 최초 사본은 덮어쓰지 않습니다. 근거 사례도 이번 실행 증거에 보존합니다. 정식 문서를 반영합니다. 스텝은 흐름의 `instructionFile` 연결을, 참조 자료는 해당 자료를 읽도록 적힌 단계 지침과 실제 파일을 확인합니다. 사용 경로를 확인하고 반영한 내용과 근거를 이번 실행 증거에 남깁니다. 근거 사례는 지우지 않습니다. 반영 위치나 권한을 확정하지 못한 내용은 반영 완료로 보고하지 않습니다.

미검증 개선안과 시험 기록은 이번 실행 증거에 남깁니다. 상황, 새로 알게 된 내용, 다음에 활용할 점과 적용 범위를 적습니다. 별도 학습 저장소는 사용자와 역할 및 읽는 경로를 확정한 경우에만 사용합니다. 전역 학습 파일을 새로 만들거나 모든 업무에서 읽도록 하지 않습니다.

## 미확정 개선안

미확정 개선안이 없으면 아래 후보 시험은 건너뛰고 보고합니다. 아래 후보 작성과 시험은 미검증 개선안에만 적용합니다. 개선할 근거가 없으면 새 후보나 학습 항목을 만들지 않습니다.

## 구조 판단

개선안을 만들기 전에 아래 질문에 답합니다.

1. 한 가지 목적을 수행하나요? 무엇을 확인하면 완료했다고 판단할 수 있나요?
2. 앞뒤 작업에서 허용된 권한, 성공 조건과 실패했을 때의 대응이 같나요?
3. 작업을 합친 뒤 뒷부분이 실패하면 이미 끝난 변경이나 전송을 반복하게 되나요? 완료한 증거를 보고 중복을 막을 수 있나요?
4. 나누려는 지점의 중간 결과가 그 자체로 의미가 있나요? 다음 스텝에서 그 상태와 증거를 이어받을 수 있나요?
5. 입력하고 저장한 뒤 바로 확인하는 작업을 불필요하게 나누지는 않았나요? 반대로 오래 기다리거나 별도 승인을 받아야 해서 나눌 필요가 있나요?
6. 같은 목적의 반복 작업을 한 스텝에서 처리해도 어디서 실패했고 어떤 대상을 마쳤는지 구분할 수 있나요?

실제 관찰과 증거를 바탕으로 답하고 현재 구성을 유지할지, 스텝을 합칠지 나눌지 정합니다.
- 따로 완료 여부를 판단해야 하거나 실패했을 때 대응이 달라진다면 나누는 쪽을 검토합니다.
- 중간 결과에 별다른 의미가 없거나 앞선 작업이 끝났는지 확인하는 부분이라면 합치는 쪽을 검토합니다.

파일 길이, 클릭 수나 화면 전환만으로 결정하지 않습니다. 답을 모르는 항목은 `확인 필요`로 남깁니다. 새 분기가 필요하다면 무엇을 기준으로 나누고, 각 결과에 따라 이후 작업이 어떻게 달라지는지 설명합니다.

## 바꿀 수 있는 범위

수정할 수 있는 파일은 다음과 같습니다.
- 이번 실행의 학습 증거와 기록
- 문서별 역할에 명시된 정식 스텝과 참조 자료 중 사용자가 수정을 허용한 문서
- 후보 MD와 후보 운영 흐름 파일
- 아래 범위에서 수정하는 정식 `workflow/flows/operational.json`
- 정식 원문을 보관하는 학습 증거 파일

민감한 정보는 저장하지 않습니다. 정식 MD는 확정 지식을 직접 반영하거나 검증한 후보를 채택할 때만 바꾸며, 다른 실행에서 사용 중인 파일은 덮어쓰지 않습니다.

기존 업무 목적과 권한 안에서 스텝 MD를 개선하거나 스텝을 합치고 나눌 수 있습니다. 필요한 스텝과 조건 분기도 추가할 수 있습니다. 이를 위해 `workflow/flows/operational.json`의 `startStep`, `steps`와 상태 선언을 수정할 수 있습니다. 기존 상태의 의미와 초기값은 유지합니다. 시험을 시작할 때만 `initialState.학습계기`를 `후보시험`으로 바꿉니다.

계정, 대상과 외부 변경 권한은 기존 범위를 넓히거나 우회하지 않습니다. 필수 알림과 수신자, 성공 기준, 예약과 재시도 상한도 그대로 지킵니다. 단계 이름을 바꿔 같은 업무의 재확인 한도를 초기화하지 않습니다.

이 학습 지침과 `learn` 단계의 권한 및 진입 조건은 바꾸지 않습니다. 엔진, 실행기, 설치 설정과 검증 기준도 수정하지 않습니다. 공통 지침의 계정, 대상과 권한은 바꾸지 않습니다. 실행 모드와 개발 흐름도 바꾸지 않습니다. 문서별 역할표의 갱신은 사용자가 해당 구획 수정을 허용한 경우에만 합니다.

## 후보 작성과 사전 검증

1. 이번 실행에서 사용한 정식 흐름과 수정할 MD 원문을 학습 증거 폴더에 한 묶음으로 보관합니다. 이미 시험 중이라면 처음 보관한 원문과 경로를 유지합니다. 변경 이유, 구조 판단 결과, 성공 기준, 바꿀 파일과 되돌릴 위치는 실행 증거에 적고 학습 내용에는 미해결 개선점만 요약합니다.
2. 정식 MD는 그대로 두고 후보 MD와 후보 전체 흐름을 작성합니다. 새 분기를 판단할 근거, 허용할 응답과 상태 전달 방법을 적습니다. `contextFile`과 기존 권한은 유지하며, 한 번에 구조 후보 하나만 시험합니다.
3. 임시 사본에 후보를 적용합니다. 파일과 목적지, 상태 선언, 조건에 맞는 분기가 하나인지, 복귀와 종료가 올바른지 확인합니다. 기존 경로와 바꾼 경로를 모의 테스트한 뒤 스텝 경계를 다시 점검합니다. 모의 검사 대신 실제 외부 작업이나 전송을 하거나, 시험을 위해 같은 변경과 발송을 반복하지 않습니다.
4. 기존 테스트가 현재 구조에 묶여 있어 후보를 검사할 수 없거나 검사가 실패하면 정식 흐름을 유지합니다. 필요한 테스트 보완은 제안으로 남깁니다. 통과시키려고 기존 테스트를 지우거나 기대 결과와 검증 기준을 낮추지 않습니다.
5. 검사를 통과하면 후보 MD를 먼저 준비하고 마지막에 운영 흐름 파일을 원자적으로 교체합니다. 현재 실행은 이미 읽은 흐름대로 마치고 후보는 다음 실행부터 적용합니다. 다른 실행의 파일 수정과 충돌하면 적용하지 않습니다. `학습계기`는 `후보시험`으로 설정합니다.

## 실제 시험과 채택

이번 실행에 실제로 전달된 후보와 작업 증거를 평가합니다. 후보를 실제로 수행했고 성공 기준도 충족한 실행만 셉니다. 방금 만든 후보는 아직 검증한 것이 아닙니다. 대상 예외를 만나지 않았다면 그 예외 대응도 검증됐다고 기록하지 않습니다.

대상 예외, 바꾼 분기와 기존 정상 동작을 실제로 검증하고 사전에 정한 성공 기준을 충족하면 후보 전체 흐름을 정식으로 채택합니다. 반복 횟수만으로 채택하지 않습니다. 실패하거나 기존 동작을 망가뜨렸다면 보관한 정식 흐름과 원래 지침 연결로 되돌립니다. 시험이 끝나면 `학습계기`를 `없음`으로 돌립니다. 후보 내용이 바뀌면 성공 횟수는 새로 셉니다. 채택하거나 되돌린 이유는 실행 증거에 보존합니다. 채택한 내용은 정식 지침에 반영하고, 실행 증거에는 채택 여부와 미해결 항목을 구분합니다.

되돌릴 때는 이미 수행한 외부 변경과 전송 내역도 실행 증거에 적습니다. 같은 작업을 중복해서 수행하지 않도록 합니다.

## 보고

수정한 파일을 다시 읽어 확인합니다. 실제로 바꾼 내용, 후보를 검증한 범위와 아직 확인하지 못한 부분, 다음 실행부터 적용되는지를 짧게 보고합니다. 필요한 검증이나 반영을 끝내지 못했다면 `학습불가`로 보고합니다.
