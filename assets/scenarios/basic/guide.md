# 기본 유형

사이트에 의존하지 않는 업무를 시작할 때 사용합니다. 이 유형에는 파일 목록 보고서 예제가 들어 있습니다. `template/`을 복사하고 대상, 계정, 권한과 알림 방법을 확정한 뒤 업무 지침을 조정합니다. [구체적인 사례](examples/file-list-report.md)를 참고하세요.

흐름은 `work → notify → cleanup`입니다. 업무 실패는 `review`에서 검토하고 같은 업무로 최대 두 번 복귀합니다. 해결되지 않아도 실패 결과를 알리고 정리합니다. 알림 실패 검토는 같은 지침을 쓰지만 검토 단계에서 직접 보내지 않습니다.

정상 실행은 학습하지 않습니다. 예외, 복구 또는 후보 시험이 있을 때만 `learn`으로 갑니다. 알림과 정리가 끝난 업무 실패는 `handed_off`, 둘 중 하나라도 실패하면 `incomplete`입니다. 학습불가는 이미 성공한 업무를 실패로 바꾸지 않습니다.

실행기와 예약 설치 파일도 포함합니다. 예약은 매시간 지정 분에 실행하는 예시이며 실제 등록은 승인 후 별도로 수행합니다. 모의 검사 통과는 실제 에이전트의 파일 처리나 전송 성공을 증명하지 않습니다.

## 학습 권한

학습을 허용할지와 수정 가능한 범위를 제작 시 사용자와 확정하고 `workflow/context.md`의 `__LEARNING_POLICY__`에 적습니다. 핵심 단계가 포함됐다고 자동 개선 권한이 생기지는 않습니다. 금지됐거나 범위가 미확정이면 지침과 메모리를 바꾸지 않고 현재 실행 증거에 미수행 이유만 남깁니다. 필요하면 제작 시 학습 분기를 제외합니다. 기존 사용자 승인 범위를 넓히지 않습니다.
