# 시나리오 유형 선택

먼저 업무의 목적과 필요한 작업을 보고 유형을 고릅니다. 사이트 이름만 같다는 이유로 선택하지 않습니다. 해당 유형의 `guide.md`와 관련 사례를 읽고 `template/`을 바탕으로 작성합니다.

| 유형 | 선택할 때 | 안내 |
| --- | --- | --- |
| 브라우저 상태 확인과 조치 | 화면에서 상태를 확인하고, 허용된 조치와 결과 알림이 필요한 업무 | [browser-monitor](browser-monitor/guide.md) |
| 기본 뼈대 | 맞는 유형이 없고 검토, 알림, 자원 정리와 학습을 갖춘 공통 구조에서 시작할 업무 | [basic](basic/guide.md) |

적합한 유형이 없으면 `basic`에서 시작합니다. 기본형에는 업무와 결과 검증, 예외 검토와 재확인, 결과 알림, 자원 정리, 메모리와 조건부 학습, 예약 설치 예시가 들어 있습니다. 브라우저나 특정 알림 서비스를 전제로 하지 않습니다.

학습과 외부 변경 권한은 사용자와 별도로 확정합니다. 업무에 필요 없는 단계는 줄이고 연결과 테스트를 함께 맞춥니다. 맞지 않는 유형의 단계를 형식적으로 채우지 않습니다.

## 사례와 유형 추가

기존 유형으로 처리할 수 있는 사례는 해당 유형의 `examples/`에 추가합니다. 작업 방식이 달라 새 유형이 필요하면 다음 구조로 만들고 위 목록에 등록합니다.

```text
<type>/
├── guide.md
├── examples/             실제 적용 사례가 있을 때 추가
└── template/             생성할 파일의 원본
```

`guide.md`에는 적합한 업무와 맞지 않는 업무, 필요한 환경과 권한, 구성 시 바꿀 부분, 실제 검증 범위를 적습니다. `template/`에는 그 유형에 필요한 파일과 모의 테스트를 한 벌로 둡니다. `examples/`에는 적용한 흐름과 차이점, 검증한 범위를 남기고 계정이나 고객의 비공개 정보는 넣지 않습니다.

유형을 추가할 때마다 `SKILL.md`를 바꿀 필요는 없습니다. 배포 업데이트는 제작용 자료를 갱신하며 이미 생성된 사용자의 시나리오 파일은 교체하지 않습니다.
