# 브라우저 상태 확인과 조치

## 이 유형을 고를 때

브라우저 화면에서 대상의 상태를 확인하고, 필요한 경우 허용된 조치를 한 뒤 결과를 알리는 업무에 사용합니다. [예약 상품 확인 사례](examples/booking-availability.md)를 참고할 수 있습니다.

파일 처리처럼 브라우저를 쓰지 않는 업무라면 [기본 뼈대](../basic/guide.md)에서 시작합니다. 기본형에도 검토와 알림, 자원 정리와 학습이 들어 있지만 탭과 전송 화면을 전제로 하지 않습니다. 입력과 제출이 중심인 업무도 이 확인 흐름에 억지로 맞추지 않습니다.

## 들어 있는 구성

`template/`의 기본 흐름은 업무 수행, 결과 알림, 작업 탭 정리입니다. 문제가 생기면 검토 후 원래 단계로 돌아가며, 예외 처리 뒤에는 학습 단계를 거칠 수 있습니다.

- 업무 대상과 권한은 `workflow/context.md`에 적습니다.
- 업무 절차와 성공 조건은 `workflow/steps/work.md`에 작성합니다. 권한이나 완료 조건이 다르면 [스텝 경계 체크리스트](template/workflow/step-boundary-checklist.md)를 보고 나눕니다.
- 알림 수신자와 전송 방법은 `workflow/steps/notify.md`에 작성합니다. 기본 예시는 메시지 본문과 전송 화면의 증거를 확인합니다. API나 파일을 증거로 쓸 업무라면 확인 방법과 완료 조건도 맞춰 바꿉니다.
- 자동 개선을 허용하지 않으면 `learn`과 관련 상태 및 분기를 제외합니다. 학습 여부는 템플릿이 아니라 사용자와 확인한 범위에 따릅니다.
- 단계를 바꾸면 `flow.json`의 연결과 상태 선언, `maintenance/tests/`의 업무별 기대 결과도 함께 맞춥니다.

## 실행과 예약

사용할 OS의 실행기와 설치 스크립트를 선택합니다. 직접 실행은 `run.sh` 또는 `run.ps1`을 사용합니다. 예약 설치 예시는 매시 지정 분 실행이며 기본값은 30분입니다. 다른 일정이나 실행 계기가 필요하면 설치와 해제 방법도 그에 맞게 작성하고 검증합니다.

macOS 예약은 로그인한 사용자의 LaunchAgent, Windows 예약은 같은 사용자의 Interactive/Limited 작업을 사용합니다. Linux나 로그아웃 상태의 서버 실행을 검증한 템플릿은 아닙니다.

## 검증 범위

네이버 예약 확인에서 사용한 업무 흐름을 일반화한 유형입니다. 공유 엔진과 이 유형의 분기, 알림 재확인, 정리와 학습 경로는 가짜 CLI로 검사합니다. 실제 대상 사이트의 화면과 작업 성공은 새 시나리오마다 따로 확인해야 합니다. Windows 네이티브 실행은 해당 환경에서 별도 검증이 필요합니다.
